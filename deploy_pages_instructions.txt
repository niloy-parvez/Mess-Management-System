Add repository secret (must be done in GitHub UI)
-----------------------------------------------
The Actions workflow expects a repository secret named: VITE_API_BASE_URL
Set this to the production backend base URL (ending with /api), for example:
  https://api.mydomain.com/api

GitHub UI steps:
- Go to your repository on GitHub
- Settings → Secrets and variables → Actions → New repository secret
- Name: VITE_API_BASE_URL
- Value: https://<your-production-backend-domain>/api
- Save secret

Configure GitHub Pages source
-----------------------------
Ensure Pages is set to use GitHub Actions as the source:
- Go to Settings → Pages → Build and deployment
- Source: GitHub Actions

Trigger the workflow
--------------------
- The workflow triggers on push to main OR master and on workflow_dispatch
- After pushing, go to Actions → Deploy Frontend to GitHub Pages → select the run
- Monitor the steps: checkout → setup-node → npm ci → type-check → build → configure-pages → upload-pages-artifact → deploy-pages

Verification after workflow completes
-------------------------------------
1) Check the workflow run completed successfully (green check).
2) Visit https://<username>.github.io/<repository-name>/
   For this repo: https://niloy-parvez.github.io/Mess-Management-System/
3) Verify root loads the app. For SPA route testing, verify:
   - /login
   - /register
   - /dashboard
   NOTE: Authentication requires your backend to be deployed and VITE_API_BASE_URL secret set to the backend URL.

If you see 404 or asset 404 errors after deployment
---------------------------------------------------
- Confirm the workflow used NODE_ENV=production and that built dist/index.html references '/Mess-Management-System/assets/...'.
- Confirm repository Pages setting is "GitHub Actions" and that the published site path matches the repository name.
- If assets 404, check the action logs for the build step and the deployed files list.

If backend is not deployed
--------------------------
- The frontend app will load but API calls will fail (CORS/network error). Do not expose SUPABASE_SERVICE_ROLE_KEY in frontend. Provide VITE_API_BASE_URL pointing to a deployed backend to enable auth/API behavior.
